# ALIVE Discovery

Use this skill before implementation when the desired outcome, user flow, scope, or tradeoff is unclear. Read [discovery-brief.md](references/discovery-brief.md), inspect only the repository evidence needed to clarify the request, and save a plan under `documents/plans/` when a durable artifact is useful.

1. Restate the user problem and desired outcome in observable terms.
2. Separate known facts, assumptions, decisions, open questions, and constraints.
3. Map the smallest affected user flow and existing product boundary.
4. Define non-goals, acceptance criteria, risks, and the smallest viable slice.
5. Resolve ambiguity from the repository when possible; ask only when the answer changes scope or safety.
6. Hand a clear brief to `$alive-engineering-workflow` for planning or change.

Do not invent screens, dependencies, APIs, or architecture to make an idea look complete. Do not turn discovery into implementation. Return problem, outcome, assumptions, scope, non-goals, acceptance criteria, risks, and recommended next mode.
