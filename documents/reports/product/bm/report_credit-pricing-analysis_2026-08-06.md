# ALIVE 크레딧 BM 및 AI 사용량 통합안

## 결과

ALIVE의 초기 BM은 구독제보다 `시간 회복형 무료 에너지 + 유료 크레딧 충전` 구조가 적합하다. 첫 몰입은 무료로 보장하고, 무료 에너지와 가입 보너스를 소진한 뒤에도 계속 사용하려는 고사용자의 추가 대화·피드·이미지·캐릭터 상호작용에서 매출을 만든다.

기존 가격안은 유지하되, 기능별 원가와 현재 프로젝트의 AI 호출 구조를 반영해 다음 방향으로 통합한다.

- 기준 단가: `1C ≈ 10원`
- 무료 구조: `100%에서 사용한 시점부터 6시간마다 무료 회복 에너지 25% 회복`, 최대 100%
- 가입 보너스: 온보딩 행동에 따라 총 150C 지급
- 메인 상품: 30,000원 / 3,150C
- 첫 결제: 최종 지급량에 추가 10% 지급 검토
- AI 과금: 기본 대화 1C, 문맥형 2C, 긴 기억·관계형 2C, Pro 5C, Pro 서사형 7C
- 피드 생성 3C, 이미지 이해 5C, 캐릭터 간 상호작용 5~8C는 별도 flow로 확정 필요

현재 저장소에는 에너지·보너스/구매 잔액·사용 원장·AI 차감과 크레딧 UI가 1차 구현돼 있다. 결제와 영수증 검증은 아직 비활성 상태이며, 운영 검증 전에는 실제 판매를 열지 않는다.

## 1. BM 핵심 방향

### 1.1 추천 BM

| 구분 | 권장안 |
| --- | --- |
| 기본 구조 | 무료 에너지 + 유료 크레딧 |
| 무료 에너지 | 시간이 지나면 자동 회복되는 무료 사용량 |
| 유료 크레딧 | 무료 에너지 소진 후 계속 이용하기 위한 재화 |
| 가입 보너스 | 첫 캐릭터와 첫 대화까지 완료하도록 행동별 분할 지급 |
| 첫 결제 혜택 | 첫 구매 한정 최종 지급량 +10% 검토 |
| 기준 단가 | 1C ≈ 10원 |
| 핵심 메시지 | 첫 몰입은 무료로 보장하고, 고사용자의 추가 이용에서 매출 발생 |

### 1.2 구독제보다 충전형이 적합한 이유

- ALIVE의 사용량은 매일 일정하지 않고, 캐릭터·피드·DM에 따라 변동된다.
- 초기 사용자는 매일 쓰지 않을 수 있어 구독 결제보다 일회 충전의 심리적 부담이 낮다.
- 캐릭터 SNS 경험은 사용량이 많아질수록 가치가 커지므로, 고사용자에게 자연스럽게 과금할 수 있다.
- 무료 에너지와 가입 보너스를 통해 결제 전에 캐릭터의 말투·관계·피드 경험을 충분히 보여줄 수 있다.

## 2. 무료 에너지 설계

| 항목 | 권장안 |
| --- | --- |
| 명칭 | 무료 회복 에너지 |
| 성격 | 유료 크레딧과 별도로 관리되는 무료 사용량 |
| 회복 방식 | 시간 회복형 |
| 회복 주기 | 6시간마다 최대치의 25% 회복 |
| 기준 시점 | 100%에서 처음 사용한 시각. 100% 미만에서는 추가 사용해도 기존 주기 유지 |
| 자정 초기화 | 없음. 달력 날짜가 아니라 6시간 간격으로 회복 |
| 최대 보유량 | 100% |
| 100% 기준 사용량 | 기본 대화 약 10~15회 |
| 소진 후 | 유료 크레딧으로 계속 이용 |
| 초과분 처리 | 최대치 초과 충전 및 회복 시간 이월 없음 |

기능별 에너지 소모율은 다음처럼 시작할 수 있다.

| 기능 | 데일리 에너지 소모 | 비고 |
| --- | ---: | --- |
| 기본 DM 1회 | 5~8% | 약 10~15회 사용 가능 |
| 긴 응답·고품질 대화 | 15~25% | Pro 또는 긴 문맥형 |
| 이미지 이해 | 25~40% | 이미지 처리 원가와 지연 반영 |
| 피드 글 생성 | 10~20% | 게시글 생성 및 저장 |
| 캐릭터 간 상호작용 | 20~30% | 다중 턴이면 최대치 기준 필요 |

### 에너지와 크레딧의 관계

무료 회복 에너지는 사용자에게 무료 경험을 제공하는 소모량이고, 크레딧은 에너지를 모두 사용한 뒤에도 기능을 계속 이용하기 위한 재화다. 100%에서 처음 사용한 시점에 회복 주기가 시작되고, 100% 미만에서 추가로 사용해도 진행 중인 주기는 초기화되지 않는다. 에너지가 다시 100%에 도달하면 남은 회복 시간은 누적하지 않으며, 다음 사용 시점부터 다시 6시간을 채워야 25%가 회복된다. 같은 AI 호출이라도 에너지를 사용할 때와 크레딧을 사용할 때의 기능 품질을 다르게 만들면 안 된다.

## 3. 가입 보너스와 첫 결제

### 3.1 가입 보너스

| 행동 | 지급 크레딧 |
| --- | ---: |
| 회원가입 완료 | 50C |
| 첫 캐릭터 생성 완료 | 50C |
| 첫 DM 완료 | 50C |
| 총 체험 가능량 | 150C |

가입 즉시 150C를 전부 주지 않고 행동별로 나누면 가입 후 이탈보다 캐릭터 생성과 첫 대화까지 이어지는 비율을 높일 수 있다.

보상은 계정별 각 이벤트에서 한 번만 지급하며 이미 지급된 기존 사용자 잔액은 소급 차감하지 않는다. 현재 보너스와 구매 크레딧은 만료 없이 누적되므로, 다중 계정·자동 호출 방지와 지급 이벤트 중복 방지가 필수다. 지급 이벤트는 `user_id + event_code`를 유일 키로 기록한다.

### 3.2 일반 가격안

| 가격 | 기본 지급 기준 | 보너스 | 최종 지급 | 포지션 |
| ---: | ---: | ---: | ---: | --- |
| 5,000원 | 500C | 없음 | 500C | 첫 결제 진입 |
| 10,000원 | 1,000C | 없음 | 1,000C | 기본 구매 |
| 30,000원 | 3,000C | 5% | 3,150C | 메인 상품 |
| 50,000원 | 5,000C | 10% | 5,500C | 반복 유저 |
| 100,000원 | 10,000C | 15% | 11,500C | 고사용자 |

실질 단가는 5,000원·10,000원 상품이 10원/C, 30,000원 상품이 약 9.52원/C, 50,000원 상품이 약 9.09원/C, 100,000원 상품이 약 8.70원/C다.

### 3.3 첫 구매 혜택

첫 구매 2배는 일반 상품의 5~15% 보너스 구조와 차이가 너무 크고, 이후 정상 가격으로 돌아갈 때 사용자가 손실로 느낄 가능성이 있다. 초기에는 기존 상품 보너스에 **첫 구매 추가 10%**만 얹는 방식이 적정하다.

| 첫 구매 상품 | 일반 최종 지급 | 첫 구매 추가 10% 적용 시 |
| ---: | ---: | ---: |
| 5,000원 | 500C | 550C |
| 10,000원 | 1,000C | 1,100C |
| 30,000원 | 3,150C | 3,465C |
| 50,000원 | 5,500C | 6,050C |
| 100,000원 | 11,500C | 12,650C |

첫 구매 추가 10%는 한 계정에서 최초 1회만 적용한다. 구매 상품에 따라 적용 범위를 다르게 두기보다 전체 상품에 동일하게 적용하는 편이 설명과 구현이 쉽다.

첫 구매 추가분은 결제 화면에서 “기본 지급 + 상품 보너스 + 첫 구매 보너스”를 최종 지급량 하나로 명확하게 보여준다.

### 3.4 보너스 재화 운영 권장

가입 보너스와 구매 크레딧은 사용자 화면에서 모두 `C`로 표시할 수 있지만, 서버 원장에서는 출처를 구분해야 한다.

| 재화 | 권장 정책 |
| --- | --- |
| 구매 크레딧 | 무기한 사용, 환불 시 잔여분 기준 처리 |
| 첫 구매 보너스 | 구매 거래에 연결, 거래 환불 시 회수 가능하도록 기록 |
| 가입·온보딩 보너스 | 무료 체험용 별도 grant로 기록 |
| 무료 보너스 유효기간 | 베타 기간 무기한. 만료 도입 시 별도 정책·데이터 모델 필요 |
| 사용 순서 | 무료 회복 에너지 → 무료 보너스 → 구매 크레딧 |
| 무료 보너스 사용처 | 일반·문맥형·이미지 기능 허용, Pro 기능은 구매 크레딧만 허용 |

무료 보너스에 만료를 적용한다면 가입·캐릭터 생성·첫 DM 화면에서 만료일을 명확히 안내해야 한다. 숨겨진 만료는 결제 신뢰를 해칠 수 있다.

### 4.1 AI 기능별 권장 크레딧

| 기능 | 모델 | 권장 크레딧 | 해석 |

### 4.2 제공받은 원가 추정치

아래 값은 이번에 전달받은 원가 추정치이며, 실제 공급자 청구액이 아니라 출시 전 검증이 필요한 가정값이다.

| 입력 + 출력 규모 | Flash 원가 | Pro 원가 |
| --- | ---: | ---: |
| 입력 3,000자 + 출력 1,800자 | 약 4.8~6.5원 | 약 19~26원 |
| 입력 6,000자 + 출력 1,800자 | 약 6.0~7.8원 | 약 24.5~31.5원 |
| 입력 10,000자 + 출력 1,800자 | 약 7.7~9.5원 | 약 31.5~38.5원 |

### 4.3 원가 대비 판단

- Flash 기본 대화 1C는 매출 8.70~10원/C 기준으로, 긴 문맥 10,000자까지 사용하면 원가 여유가 작아질 수 있다.
- Flash 문맥형 2C는 매출 약 17.39~20원 수준이므로, 제공된 원가 범위에서는 비교적 안전하다.
- 피드 생성 3C는 Flash 원가보다 높은 가격이지만, 게시글 저장·SNS 경험·자동 반응을 포함한 제품 가치 과금으로 설명할 수 있다.
- Pro 5C는 매출 약 43.48~50원이고 제공된 Pro 원가 범위가 최대 38.5원이므로, 플랫폼 수수료·세금·스토리지·실패 재시도 비용을 고려하면 상한 문맥을 반드시 둬야 한다.
- Pro 7C는 긴 추론·서사형 작업의 원가 여유가 더 크다.
- Flash 긴 기억·관계형 2C와 Pro 고품질 5C를 구분하면, 같은 “긴 대화”라도 모델 선택에 따른 가격 이유를 설명할 수 있다.

이 판단은 플랫폼 수수료·부가세·환율·실제 토큰화·재시도 비용을 포함하지 않은 매출-모델원가 비교다. 따라서 현재 가격은 “원가상 가능성이 있는 초기안”이지, 최종 마진이 검증된 가격은 아니다.

## 5. 무료 기능과 유료 기능

| 기능 | 무료 경험 | 유료 크레딧 |
| --- | --- | --- |
| 기본 대화 | 데일리 에너지 범위 내 제공 | 에너지 소진 후 계속 이용 |
| 장기기억 | 기본 기능 제공 | 저장 슬롯·고급 문맥 확장 검토 |
| 유저노트 | 기본 기능 제공 | 슬롯 확장 검토 |
| 피드 생성 | 첫 생성 및 기본 횟수 제공 | 추가 생성 3C |
| 이미지 이해 | 소량 체험 제공 | 추가 이미지 이해 5C |
| 캐릭터 간 상호작용 | 제한적 경험 제공 | 추가 상호작용 5~8C |
| 캐릭터 생성·분석 | 첫 경험에 포함 | 반복 분석 과금 여부 별도 결정 |

여기서 “장기기억 2C”는 기억 저장 자체를 유료화한다는 뜻이 아니라, 기억과 관계 문맥을 많이 포함한 AI 응답의 처리 등급을 의미하는 것으로 정리한다. 기본 기억 기능을 지나치게 잠그면 경쟁 서비스 대비 진입 장벽이 높아질 수 있다.

무료 에너지에서 유료 크레딧으로 넘어갈 때는 동일한 기능의 품질을 바꾸지 않는다. 다만 Pro·이미지·긴 자동대화는 무료 보너스 사용처에서 제외하거나, 사용자에게 예상 소모량을 먼저 보여주는 방식으로 원가를 보호한다.

## 11. 검증과 남은 불확실성

### 확인된 사실

- 현재 크레딧 화면은 목업이며 실제 결제는 발생하지 않는다.
- 현재 AI는 `/api/ai/generate`와 서버 피드 생성 경로를 사용한다.
- 현재 백엔드는 사용자별 일일 호출 제한과 월간 추정 비용 제한을 갖는다.
- 현재 프론트 모델명과 백엔드 공급자 모델명 사이에 변환 계층이 있다.
- 현재 프로젝트에는 실제 크레딧 잔액·원장·결제 검증 기능이 없다.

### 아직 검증하지 못한 것

- 제공받은 Gemini 원가 추정치의 최신 공급자 청구액 일치 여부
- 플랫폼 수수료·부가세·환율 반영 후 실제 마진
- 실제 사용자별 입력·출력 문맥 분포
- 첫 구매 추가 10%가 결제 전환율과 환불률에 미치는 영향
- 6시간·25% 에너지 회복의 재방문 효과
- 자동 게시글·자동 댓글의 실제 호출량과 사용자 가치

### 남은 위험

1. 1C 가격은 짧은 Flash 요청에는 가능하지만, 긴 문맥과 실패 재시도를 포함하면 마진이 좁아질 수 있다.
2. Pro 5C는 플랫폼 수수료와 운영비를 포함하면 상한 문맥이 필요하다.
3. 가입 150C와 첫 구매 추가 보너스는 전환에는 유리하지만 다중 계정·환불 악용 위험이 있다.
4. 자동 기능이 사용자 모르게 유료 크레딧을 소모하면 신뢰 문제가 생긴다.
5. 피드 생성 3C와 캐릭터 상호작용 5~8C는 모델 원가만으로는 설명되지 않으므로 제품 가치와 사용량 상한을 함께 정의해야 한다.

ALIVE는 구독제보다 크레딧 충전형 BM이 적합하며, 가입 보너스와 시간 회복형 데일리 에너지로 첫 몰입을 보장하고, 무료 사용량을 초과한 고사용자의 추가 대화·피드·이미지·캐릭터 상호작용에서 매출을 만드는 구조가 적절하다.
