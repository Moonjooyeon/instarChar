# Gemini 3.6 전환 후 크레딧·마진 재점검

> 이 감사 시점의 위험 진단은 유지한다. 실제 원가 계측·상한·가격 조정 후의 운영 기준은 [AI 기능별 단위경제 기준선](report_ai-unit-economics-baseline_2026-08-12.md)이 대체한다.

- 작성일: 2026-08-12
- 범위: `gemini-3.6-flash` 및 `gemini-3.1-pro-preview` 전환, 피드 중복 환급, 피드 프롬프트 다양성·온도 변경
- 성격: 코드와 기존 라이브 샘플을 기준으로 한 분석 보고서. MonoGPT 실제 청구 단가와 운영 채널별 정산서는 연결되지 않아 확정 손익 보고서는 아니다.

## 현재 상태

- 운영 환경 파일은 Fast에 `gemini-3.6-flash`, Pro에 `gemini-3.1-pro-preview`를 지정한다.
- `.env.example`도 같은 값을 제공하지만 `Settings`의 환경변수 미설정 fallback은 아직 `gemini-2.5-flash`, `gemini-2.5-pro`다. 배포 환경에서 두 환경변수를 반드시 설정해야 정책 원가 가정과 실제 모델이 일치한다.
- flow 정책의 원가 예약은 Flash `$1.50 / $7.50`, Pro `$2.00 / $12.00` (각각 입력/출력 1M tokens), 최대 두 번 provider 호출을 기준으로 한다.
- Gemini 응답의 토큰 수는 저장하지만, `gemini_usage()`는 USD 원가를 계산하지 않고 `measured=False`를 반환한다. 따라서 실제 청구 원가는 항상 `$0`으로 저장되고, 월 원가 한도는 실제값이 아니라 예약 상한을 유지한다.

공식 모델 단가는 Gemini 3.6 Flash `$1.50 / $7.50`, Gemini 3.1 Pro `$2.00 / $12.00`으로 사용했다. 출력 가격에는 사고 토큰이 포함된다고 가정한다.

## 계산 가정

- 환율 계획값: `$1 = 1,400원`.
- 매출 단가는 가장 보수적인 현금 구매 조건인 `99,000원 / 12,650C`(100,000C 상품의 상품 보너스와 첫 구매 10% 보너스 포함)에 앱마켓 15%를 차감한 `6.65원/C`다.
- 서버·DB·CS·환불·부가세·MonoGPT 중개 마진은 제외했다. MonoGPT 계약 단가가 Google 공개 단가보다 높으면 아래 마진은 추가로 낮아진다.
- `정책 상한 원가`는 코드의 `max_input_chars × 2` input tokens와 `max_output_tokens`, 최대 provider 호출 2회를 그대로 적용했다. 실사용 p95가 아니라 API 한도와 재시도까지 포함한 안전 상한이다.

## 기존 라이브 샘플의 낮은 맥락 참고치

2026-08-10 MonoGPT 재점검 샘플은 3.6 Flash에서 기본 DM `30 input / 39 output`, 피드 `53 input / 90 output`을 기록했다. 공개 단가와 위 환율로 환산하면 각각 약 `0.47원`, `1.06원`이다. 보수 매출 기준 마진은 각각 약 `93%`, `95%`다. 3.1 Pro 캐릭터 분석 샘플은 `184 / 175`로 약 `3.46원`; 유료 5C일 때 약 `90%`다.

이는 매우 짧은 smoke 입력이며 최근 글 8개, 장기 DM 맥락, 재시도, 사고 토큰의 p95를 대표하지 않는다. 특히 기존 3.6 평가에서는 후보 출력 토큰이 `0`인데 사고 토큰만 보고된 샘플도 있어, provider usage 필드만으로 출력 청구 토큰을 안정적으로 재구성할 수 없다.

## 중복 환급·온도·프롬프트 변경의 비용 영향

- 자동 근황은 최근 글과 유사도가 78% 이상이면 저장과 2C 확정을 하지 않고 `POST_TOO_SIMILAR`로 환급한다. 사용자에게는 올바른 동작이지만 provider 호출 뒤에 판정하므로 회사에는 생성 원가가 남는다.
- 자동 스케줄러는 이 실패를 기록한 뒤 60초부터 지수 backoff로 다시 시도한다. 따라서 허용되는 글 한 편의 실질 provider 원가는 `1 / (1 - 중복 실패율)` 배가 된다. 예: 실패율 10%는 1.11배, 20%는 1.25배, 30%는 1.43배다.
- 현재의 짧은 피드 샘플 원가 1.06원을 기준으로 해도 10%/20%/30%에서는 약 1.17원/1.32원/1.51원이다. 2C 보수 매출 13.30원보다 낮다. 다만 실사용 p95와 MonoGPT 중개 단가는 계측되지 않아 이것을 보장할 수 없다.
- 최근 글·생성 시간·variation seed 전달은 입력 토큰을 늘린다. 8개 최근 글을 넣는 현재 구조는 `20,000자` 입력 한도 안에서만 동작하므로 정책 상한은 바뀌지 않았다. 온도 0.75는 토큰 단가를 직접 바꾸지 않지만, 출력 길이·중복률에는 영향을 줄 수 있다.

## 결론과 권장 조치

1. Fast는 `gemini-3.6-flash`를 유지한다. 3.5 Flash보다 출력 단가가 낮고, 현재 피드·DM의 짧은 응답에 맞는다.
2. Pro는 `gemini-3.1-pro-preview`를 유지하되, preview 모델이므로 출시 전 GA 모델 또는 공급자 유지 정책을 확인한다. 5C 가격은 실사용 분포가 짧다면 가능하지만 정책 상한으로는 안전하지 않다.
3. 비용 정책을 바꾸기 전에 `ProviderUsage.cost_usd`와 `measured`를 실제 토큰·계약 단가로 계산하고 저장해야 한다. 그래야 p50/p95/p99, 중복 환급률, 기능별 실제 마진을 계산할 수 있다.
4. 최소 7일 shadow billing 후 flow별 p95가 보수 매출의 30%를 넘는 기능만 C 가격·입력 상한·재시도 정책을 조정한다. 지금 상한 수치만 보고 일괄 인상하는 것은 과도하다.
5. 자동 근황은 `POST_TOO_SIMILAR` 비율을 별도 지표로 저장하고 10%를 넘으면 프롬프트 또는 유사도 기준을 먼저 조정한다.
