# 테마 및 Tailwind CSS 전환 2차 검증 보고서

## 작업 범위

- 인증 로딩, 로그인 진입, 복구 화면의 라이트·다크 토큰 적용
- 로그인 전에도 모드를 전환할 수 있는 Tailwind 기반 테마 버튼 추가
- 서비스 둘러보기의 세 장면과 내부 미니 UI 토큰화
- 캐릭터 생성 3단계와 최종 확인 화면 토큰화
- 생성 단계 진행 표시를 Tailwind 유틸리티로 전환
- 레거시 스타일을 CSS cascade `components` layer로 이동
- 인증·투어·설정 화면에 `al-theme-ready` 경계 추가

## 디자인 판단

- Google과 Apple 로그인 버튼은 공식 흑백 브랜드 자산이므로 테마 색으로 재해석하지 않았다.
- 넓은 보라·핑크 그라디언트 대신 단색 강조 버튼과 따뜻한 중립 표면을 사용했다.
- 서비스 둘러보기의 미니 화면은 별도 카드 장식이 아니라 실제 제품 장면처럼 읽히도록 표면 차이와 얇은 경계선으로 구분했다.
- 작은 보조 글자의 대비가 부족했던 `faint` 토큰을 라이트 `#766e79`, 다크 `#8b8492`로 조정했다.

## 시각 검증 상태

프론트엔드 실행 프로세스가 없어 프로젝트 규칙에 따라 새 프로세스를 시작하지 않았다. 다음 검토는 이미 실행 중인 앱이 준비된 상태에서 수행한다.

## 실행 화면 검토 절차

1. 로그인 화면을 390×844와 320px 폭에서 각각 연다.
2. 우측 상단 달·해 버튼과 미리보기 버튼이 겹치지 않는지 확인한다.
3. 두 모드에서 Google·Apple 공식 버튼 이미지의 비율과 테두리가 변하지 않는지 확인한다.
4. 미리보기의 피드·만남·대화 세 장면을 이동하며 텍스트 잘림과 장면 전환 모션을 확인한다.
5. 캐릭터 생성의 인물·성격·말투 단계를 이동하며 현재·완료·대기 단계가 구분되는지 확인한다.
6. 입력 focus, placeholder, 필수·선택 배지, 비활성 다음 버튼을 두 모드에서 확인한다.
7. 최종 확인 화면에서 분석 실패, 아이디 사용 가능·중복, 저장 오류 상태를 확인한다.
8. 680px 이하 높이에서 제목, 입력, 하단 버튼이 겹치지 않고 스크롤 가능한지 확인한다.
9. 키보드만으로 테마 전환, 미리보기, 생성 단계, 최종 저장까지 이동 가능한지 확인한다.
