# 테마·Tailwind 정적 완료 감사 보고서

## 결론

라이트, 다크, 기기 설정 테마의 상태·초기 적용·저장 구조와 모든 주요 화면·오버레이의 시맨틱 색상 적용을 완료했다. Tailwind CSS를 빌드 파이프라인에 추가하고 주요 입력·액션·상태를 시맨틱 유틸리티로 전환했다.

실행 중인 프론트엔드가 없어 실제 화면 시각 검증은 수행하지 않았다. 프로젝트 규칙에 따라 새 프로세스를 시작하지 않고 아래 수동 검토 절차로 대체한다.

## 적용 범위

- 인증, 서비스 투어, 홈, 캐릭터 생성·최종 확인
- 피드 프로필, 관계·기억, 작성기, 타임라인, 댓글, 도움말
- 탐색, DM 목록, DM 대화방, 관계·기억, 제어·입력
- 계정, 교정, 안전, 공개 프로필, 세계관, 팔로우, DM 설정, 관계 결과 모달
- 라이트·다크·기기 설정 선택 UI와 초기 테마 깜빡임 방지

## 색상 시스템

- 캔버스, 전화 프레임, 표면 4단계, 본문·보조·희미한 텍스트, 경계선 2단계를 토큰화했다.
- 브랜드 포인트, 좋아요, 위험, 성공을 별도 의미색으로 분리했다.
- 라이트 모드는 순백·회색 템플릿 대신 따뜻한 종이색과 절제된 자주색을 사용했다.
- 다크 모드는 기존 캐릭터성을 보존하되 보라·핑크 면적을 줄이고 정보 위계에 집중했다.
- Google·Apple 공식 로그인과 이미지 위 가독성 오버레이는 의도적 고정 색상으로 보존했다.

## Tailwind와 레거시 상태

- Tailwind CSS 4와 Vite 플러그인을 적용했다.
- 주요 화면의 입력, 주·보조·위험 액션, 선택·비활성 상태가 시맨틱 Tailwind 유틸리티를 사용한다.
- 런타임 CSS 문자열을 제거하고 정적 스타일 진입점과 화면별 브리지로 분리했다.
- `legacy.css`는 1,323줄에서 1,158줄로 감소했다.
- 전체 CSS의 미사용 `.al-*` 셀렉터는 0건이다.
- 남은 레거시 규칙은 현재 사용 중인 구조·레이아웃이다. 실행 화면 없이 전량 제거하면 UI 회귀 위험이 커서 다음 점진 전환 대상으로 남겼다.

## 자동 검증

- `npm run typecheck`: 통과
- `npm run test:domain`: 120/120 통과
- `npm run build`: 통과
- `git diff --check`: 통과
- 모든 `.al-phone` 루트의 `al-theme-ready`: 확인
- 테마 없는 `.al-modal-bg`: 0건
- 화면별 CSS 직접 색상: 흰색 전경을 제외하고 0건
- 전체 CSS 미사용 `.al-*` 셀렉터: 0건

## 수동 화면 검토 절차

사용자 또는 개발자가 이미 실행한 앱에서 다음 순서로 확인한다.

1. 인증 화면에서 테마를 `라이트`, `다크`, `기기 설정`으로 바꾸고 새로고침 후 선택 유지와 초기 깜빡임을 확인한다.
2. 홈의 캐릭터 없음·있음 상태, 서비스 투어 3장, 캐릭터 생성과 최종 확인을 각 테마에서 확인한다.
3. 피드에서 프로필 확장, 관계·기억, 게시물 작성, 이미지 첨부, 탭 전환, 좋아요, 댓글, 도움말을 확인한다.
4. 탐색에서 검색·추가·DM·공개 프로필·세계관·팔로우 목록을 확인한다.
5. DM 목록에서 새 대화를 만들고 장면 설정, 공유 범위, 메시지 송수신, 자동 대화, 관계·기억 패널을 확인한다.
6. 이름 수정, 캐릭터 삭제, 캐해 교정, 신고, 차단, 약관 동의, 관계 제안·결과 모달을 확인한다.
7. 모바일 폭과 데스크톱 프레임에서 텍스트 대비, 포커스 링, 비활성 상태, 스크롤, 안전 영역, 키보드 입력 시 레이아웃을 확인한다.

## 수동 검토 시 중점 기준

- 라이트 모드에서 보조 텍스트와 경계선이 배경에 묻히지 않는가
- 다크 모드에서 보라·핑크가 넓은 장식 면으로 과용되지 않는가
- 좋아요·위험·성공 상태가 아이콘·문구와 함께 전달되는가
- 모달이 열린 원래 화면과 무관하게 같은 테마를 유지하는가
- 공식 로그인 버튼과 이미지 위 컨트롤의 브랜드·가독성이 유지되는가
