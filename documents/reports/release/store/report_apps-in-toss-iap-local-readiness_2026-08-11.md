# 앱인토스 인앱결제 로컬 출시 준비 감사

## 결론

**로컬 구현과 자동 검증은 출시 후보 수준으로 완료됐지만, 실제 판매를 시작할 준비는 아직 끝나지 않았다.** 현재 브랜치의 서버 권한 주문 검증, 멱등 지급, 미지급 복원, 환불 재조정, 구매 원장, 탈퇴 후 5년 보존·파기, 제한 롤아웃과 콘솔 사전 검증은 통과했다. 반면 앱인토스 콘솔 업로드, `최소 지원 버전` 선택, 실제 SKU·가격 입력, 운영 mTLS, 샌드박스 실결제, 알림 연결과 법무·운영 승인은 저장소 밖의 권한과 값이 없어 검증하지 못했다.

따라서 현재 출시 판정은 다음과 같다.

| 판정 대상 | 결과 | 의미 |
| --- | --- | --- |
| 코드 병합 후보 | **통과** | 로컬 구현·테스트·migration 증거가 준비됨 |
| 스테이징 배포 후보 | **조건부 통과** | 운영 값과 mTLS를 비밀 저장소에 주입한 뒤 시작 검증 필요 |
| 앱인토스 상품 등록 | **차단** | `.ait` 업로드와 콘솔 발급 값 필요 |
| 샌드박스 검수 | **미실행** | 상품·mTLS·테스트 기기 준비 필요 |
| 실제 판매 활성화 | **불가** | 외부 게이트와 단계적 관찰이 끝나지 않음 |

`TOSS_IAP_ENABLED`, `TOSS_IAP_PURCHASE_ENABLED`와 콘솔 상품 노출은 계속 OFF로 유지한다.

## 감사 기준

상태는 다음 네 가지로 기록한다.

- `통과`: 코드, 자동 테스트, 산출물 또는 실제 실행 증거가 있다.
- `실패`: 실행했으나 출시 조건을 만족하지 못했다.
- `미실행`: 필요한 외부 값, 권한, 환경 또는 실기기가 없어 실행하지 못했다.
- `해당 없음`: 현재 앱 기능이나 이번 출시 범위에 적용되지 않는다.

기준 문서는 [앱인토스 인앱결제 승인 후 적용 및 출시 검토 계획](../../../plans/release/store/plan_apps-in-toss-iap-integration_2026-08-11.md), [배포 및 운영 가이드](../../../guides/guide_apps-in-toss-iap-operations.md), [샌드박스 실행 가이드](../../../qa/guides/guide_apps-in-toss-iap-sandbox_2026-08-11.md)다. 공식 요구사항은 계획서의 공식 가이드 매핑을 권위 있는 기준으로 사용했다.

| 요구사항 | 상태 | 저장소 증거 | 남은 외부 증거 또는 행동 |

| IAP 포함 `.ait` 준비 | 통과 | [ashwoodfriends-alive-iap-415f3a2.ait](../../../qa/evidence/ashwoodfriends-alive-iap-415f3a2.ait), SHA-256 `9ac56dcb6ac9d88bb5e92d72acc4660fef1050cd52ef75fec38bfb5094353e56`; 최신 프런트엔드 변경 커밋도 `415f3a2` | 콘솔 `앱 출시` 업로드 |
| 콘솔 배포 ID·표시 버전·QR 확보 | 미실행 | 로컬 번들 내부 앱 이름 `ashwoodfriends-alive`, 배포 ID `019fef17-2f19-71bf-9f2c-a405896b0e3f` 확인 | 콘솔 업로드 결과와 QR 테스트 증빙 |
| 상품 폼 `최소 지원 버전` 선택 | 미실행 | 계획서에서 미니앱 번들 버전과 토스 앱 런타임 버전을 구분 | 업로드한 번들이 드롭다운에 나타나는지 확인하고 선택 |
| 소모품 5개 등록·노출 OFF | 미실행 | [상품 이미지와 매니페스트](../../../qa/evidence/apps-in-toss-iap-products/README.md), 서버 상품 정책 5개 | 실제 SKU, 공급가, VAT 포함 판매가, 승인된 상품 문구 입력 |
| 콘솔 값과 코드 정책 사전 검증 | 실패(입력 미완료) | [사전 검증기](../../../../backend/app/iap_release_check.py) 테스트 4건 통과 | 예시 매니페스트는 공급가 0원 5건을 거부함. 실제 값으로 만든 매니페스트가 `make iap-release-check`를 통과해야 함 |
| 결제 중 미디어 일시정지 | 해당 없음 | 앱에 결제 중 재생되는 오디오·영상 기능 없음 | 기능 추가 시 재검토 |

`최소 지원 버전` 목록이 빈 현재 상태에서는 값을 임의로 만들지 않는다. 먼저 `.ait`를 콘솔 `앱 출시`에 업로드해야 한다. 상품 폼의 이 값은 Android 5.234.0·iOS 5.233.0 토스 앱 런타임 게이트와 서로 다른 버전이다.

| 운영 | 로그 수집 연결, 온콜 담당자, 10분 SLA, 정산·환불 담당자 | 운영 경보·정산 게이트 |
| 대표자·법무 | 5년 보존 목적, HMAC 연결, 법적 보존 정지, 공개 문구 승인 | 약관·개인정보 게이트 |
| QA | Android/iOS 지원·미지원 버전 기기와 샌드박스 시간 | 결제·복원·환불·오류 실증 |

인증서, 개인키, Basic Auth와 HMAC 원문은 이 보고서나 Git에 넣지 않는다. 준비 여부와 만료일만 증빙한다.

## 재개 순서

1. 준비된 `.ait`를 콘솔 `앱 출시`에 업로드하고 배포 ID·표시 버전·QR을 기록한다.
2. 업로드한 버전을 상품의 `최소 지원 버전`으로 선택한다.
3. 상품 5개를 소모품·노출 OFF로 등록하고 실제 SKU·공급가·VAT 포함 판매가를 매니페스트에 기록한다.
4. `make iap-release-check IAP_RELEASE_MANIFEST=documents/qa/evidence/apps-in-toss-iap-console-manifest.json`을 통과시킨다.
5. mTLS, HMAC, migrations와 IAP 환경 변수를 스테이징에 배포하되 신규 구매는 OFF로 유지한다.
6. 샌드박스에서 성공, 취소, pending, 서버 실패 후 재진입 복원, 중복 callback, 환불과 미지원 버전을 검증한다.
7. 법무·운영·정산 승인을 받은 뒤 콘솔 노출과 신규 구매를 10%로 열고 최소 24시간 관찰한다.
8. 콘솔·내부 원장 대조가 깨끗할 때 25% → 50% → 100%로 확대한다.

위 입력이 오기 전에는 `최소 지원 버전`을 채우거나 실제 판매 플래그를 켜는 추가 로컬 행동을 하지 않는다.
