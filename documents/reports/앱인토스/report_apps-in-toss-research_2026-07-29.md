# 앱인토스(Apps in Toss) 최신 조사 보고서

## 문서 목적

`alive`를 토스 앱 안에서 제공할 수 있는지 판단하기 위한 사전 조사 자료다. 이 문서에서 말하는 "토스 인앱"은 토스의 공식 플랫폼 명칭인 **앱인토스(Apps in Toss)** 를 뜻한다.

> 정책, 수수료, SDK 지원 버전은 수시로 바뀔 수 있다. 아래 내용은 **2026-07-29**에 토스 공식 개발자센터와 공식 블로그를 기준으로 확인했다. 구현 또는 사업 의사결정 직전에 각 링크를 다시 확인해야 한다.

## 핵심 결론

앱인토스는 파트너가 개발한 서비스를 토스 앱 안에서 미니앱(App-in-App)으로 배포하는 플랫폼이다. `alive`는 기존 React 기반 서비스를 WebView SDK로 이식하는 방식이 가장 짧은 출발점이다. 다만 캐릭터 생성, AI 생성 콘텐츠, 사용자 게시물(UGC), 유료 디지털 기능이 포함될 경우 출시 검수 통과 여부는 기능 구현과 별개이므로, 착수 전에 운영 채널로 사전 검토를 받아야 한다.

## 플랫폼 개요

| 항목           | 공식 확인 내용                                                                                   |
| -------------- | ------------------------------------------------------------------------------------------------ |
| 서비스 형태    | 토스 앱 안에서 실행되는 파트너사 미니앱                                                          |
| 시작 자격      | 별도 제휴·계약 없이 콘솔 계정 생성 후 시작 가능                                                  |
| 사업자 등록    | 앱 개발·검수 시작 자체에는 필수가 아니지만, 인앱 결제 또는 정산이 필요하면 사업자 정보 등록 필요 |
| 지원 OS        | Android 7 이상, iOS 16 이상                                                                      |
| 현재 이용 대상 | 만 19세 이상 사용자                                                                              |
| 검수           | 운영·디자인·기능·보안 4단계. 공식 안내상 앱 출시 검수는 영업일 2~3일 소요                        |
| 전체 출시 예상 | 일반적으로 게임 2~4주, 비게임 2~3개월. 기능과 검수에 따라 달라짐                                 |

## 개발 구조와 선택지

앱인토스는 클라이언트 SDK와 서버 API로 구성된다. 클라이언트는 토스 앱 내 실행 환경과 네이티브 기능 연결을, 서버 API는 로그인 토큰 검증·결제 승인·알림 발송 등 서버 간 처리를 담당한다.

| 선택지           | 적합한 경우                                   | `alive`에 대한 판단                                                      |
| ---------------- | --------------------------------------------- | ------------------------------------------------------------------------ |
| WebView SDK      | 기존 웹 서비스를 빠르게 토스 앱에서 실행할 때 | 현재 React + Vite 기반 클라이언트를 활용할 수 있으므로 MVP의 우선 선택지 |
| React Native SDK | 네이티브 수준 성능·토스 앱 통합이 중요할 때   | 앱인토스 전용 UX 또는 성능 병목이 확인될 때 재검토                       |

- 두 SDK는 공통 런타임 레이어인 Granite를 사용한다.
- 새 구현은 SDK 2.x를 기준으로 해야 한다. 공식 문서에 따르면 2026-03-23 이후 SDK 1.x로 빌드한 번들은 콘솔에 업로드할 수 없다.
- WebView/React Native 어느 방식이든 `iframe`은 사용할 수 없다. 유튜브 영상 삽입만 예외이며, 일반 iframe 사용은 기능 미동작 및 보안 검수 반려 사유가 된다.

출처: [앱인토스 개발 시작](https://developers-apps-in-toss.toss.im/bedrock/intro.html), [SDK 런타임 개요 및 2.x 마이그레이션](https://developers-apps-in-toss.toss.im/bedrock/reference/framework/%EC%8B%9C%EC%9E%91%ED%95%98%EA%B8%B0/intro.html), [API 시작하기](https://developers-apps-in-toss.toss.im/api/overview.html)

## 사용할 수 있는 주요 플랫폼 기능

| 기능                  | 적용 예시                              | 연동 특성                        |
| --------------------- | -------------------------------------- | -------------------------------- |
| 토스 로그인           | `alive` 사용자 계정의 간편 가입·로그인 | 서버에서 토큰 검증 필요          |
| 토스 페이·인앱 결제   | 프리미엄 기능, 디지털 콘텐츠·권한 판매 | 결제 승인 등 서버 연동 필요      |
| 기능성 푸시·알림      | 댓글·DM·캐릭터 활동 알림               | 서버 간 API 연동 필요            |
| 프로모션(토스 포인트) | 첫 캐릭터 생성, 미션 참여 보상         | 비즈 월렛 예산 및 정책 확인 필요 |
| 토스 앱 공유 링크     | 특정 캐릭터/게시물 화면 공유           | `intoss://` 딥링크 기반          |

로그인, 결제, 기능성 메시지·알림, 프로모션 API는 파트너 서버와 앱인토스 서버 간 **mTLS** 통신이 필수다. 서버가 토스가 지정한 API 도메인으로 HTTPS 443 포트 통신을 할 수 있도록 인증서·방화벽을 준비해야 한다.

출처: [서버 API 사용 절차](https://developers-apps-in-toss.toss.im/development/integration-process.html), [토스 앱 공유 링크](https://developers-apps-in-toss.toss.im/bedrock/reference/framework/%EA%B3%B5%EC%9C%A0/getTossShareLink.html)

## 출시 및 UX 정책상 주요 제약

다음 항목은 기능 설계 초기에 반영해야 한다.

- 외부 앱 설치나 외부 웹 가입으로 사용자를 유도할 수 없다.
- 디지털 상품·콘텐츠·권한의 결제는 인앱 결제를 사용해야 한다.
- 가상자산·NFT의 소유, 이전, 저장, 거래, 중개, 발행 기능은 등록할 수 없다.
- 대출, 보험, 카드, 증권 등 금융상품 관련 서비스는 현재 등록할 수 없다.
- 토스와 미니앱의 브랜드를 사용자가 혼동하지 않도록 서비스 자체의 로고·이름·컬러를 명확히 노출해야 한다.
- 다크패턴 방지, UX 라이팅, 화면 해상도, 그래픽 리소스 사용 기준을 포함한 UI/UX 가이드를 따라야 한다.

출처: [서비스 오픈 정책](https://developers-apps-in-toss.toss.im/intro/guide.html), [UI/UX 가이드](https://developers-apps-in-toss.toss.im/design/consumer-ux-guide.html)

## 수익화와 정산

앱인토스는 인앱 결제와 인앱 광고를 지원한다. 공식 정산 문서에서 안내하는 기본 구조는 아래와 같다.

| 항목      | 문서상 수수료·정산 구조                                                                           | 주의점                                                                                |
| --------- | ------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------- |
| 인앱 결제 | 앱마켓 수수료(공급가 기준 15% 또는 30%)와 토스 수수료(결제 금액 기준 5%)가 구조상 존재            | 공식 문서상 CBT 기간 토스 수수료는 한시적으로 0%. 실제 적용률은 출시 직전 재확인 필요 |
| 인앱 광고 | 광고 송출 운영비가 광고 매출의 약 30% 수준으로 공제되고, 광고 수익의 앱인토스 수수료는 15%로 안내 | 수수료 면제 프로모션 진행 여부와 조건이 변경될 수 있음                                |
| 정산 단위 | 앱 단위가 아닌 사업자 단위로 여러 앱의 수익·비용을 합산                                           | 결제·광고 정산을 위해 사업자·계좌·세금계산서 정보 준비 필요                           |

정산액과 세금계산서 처리 방식은 앱마켓·사업자 유형·수익 종류에 따라 달라진다. 이 문서의 수수료는 사업성 추정의 참고치로만 사용하고, 계약·가격 결정에는 [공식 정산 문서](https://developers-apps-in-toss.toss.im/settlement/intro.html)를 기준으로 재검증한다.

## `alive` 적용 판단

### 적합한 점

- 캐릭터 활동, 피드, 댓글, DM처럼 반복 방문을 유도하는 콘텐츠형 서비스는 토스 앱 내 진입·알림·공유 기능과 결합 가능성이 있다.
- 기존 React + Vite 기반 프런트엔드를 활용할 수 있어, WebView SDK 기반의 초기 이식 범위를 상대적으로 작게 잡을 수 있다.
- 토스 로그인은 신규 사용자 가입 단계를 줄이는 데 활용할 수 있다.

### 확인이 필요한 점

- 사용자 생성 콘텐츠와 AI 생성 콘텐츠의 운영·신고·차단·연령 적합성 기준
- 캐릭터 간 DM과 댓글의 모더레이션, 신고 처리, 고객 문의 경로
- 유료 구독·프리미엄 기능이 "디지털 상품·권한"으로 분류되는 결제 흐름
- 외부 OAuth·외부 결제·외부 웹 진입 등 현재 플로우 중 정책에 맞지 않는 부분
- 서비스가 만 19세 이상 사용자만 이용 가능한 환경과 제품 타깃에 맞는지

위 사항은 공개 문서만으로 허용 여부를 단정할 수 없다. 앱 등록 전에 콘솔 운영 문의 또는 채널톡을 통해 서비스 기획서와 함께 사전 검토를 요청해야 한다.

## 권장 사전 검토 순서

- [ ] 토스 콘솔 계정을 생성하고, `alive`의 핵심 사용자 흐름과 수익화 방식을 한 페이지로 정리한다.
- [ ] AI/UGC/DM/유료 기능의 허용 범위를 운영 채널에 사전 문의한다.
- [ ] WebView SDK 2.x 기준으로 최소 화면(진입, 로그인, 피드, 캐릭터 상세)을 샌드박스에서 검증한다.
- [ ] mTLS가 필요한 기능을 확정하고, FastAPI 서버의 인증서 보관·갱신·API 호출 경로를 설계한다.
- [ ] 외부 이동·결제·가입 요소를 제거하거나 토스 제공 기능으로 대체한다.
- [ ] UI/UX 가이드와 출시 정책 기준으로 출시 전 자체 점검표를 작성한다.
