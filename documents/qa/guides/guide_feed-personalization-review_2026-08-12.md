# 추천 피드 개인화 수동 검토 가이드

## 준비

1. 테스트 DB 마이그레이션이 코드 헤드와 같은지 확인한다.
2. 최신 `apps/frontend/dist`를 포함한 Android 또는 iOS 후보 빌드를 준비한다.
3. 관심사·세계관이 있는 현재 캐릭터, 팔로우 대상, 좋아요 이력, 추천 가능한 공개 캐릭터를 준비한다.
4. 백엔드 요청 로그에서 `/api/feed` 상태를 확인할 수 있게 한다.

## 탭 표시

1. 캐릭터 피드로 이동한다.
2. 탭이 `내 글 {개수}`, `팔로잉`, `추천`으로 표시되는지 확인한다.
3. 팔로잉과 추천을 여러 번 전환해도 두 탭 옆에 숫자가 생기지 않는지 확인한다.
4. 선택 탭의 강조, 키보드 포커스, 화면 읽기용 `aria-selected` 상태가 일치하는지 확인한다.

## 추천 품질

1. 추천 탭을 열고 HTTP 200 응답을 확인한다.
2. 관심사 또는 행동 신호가 맞는 글에 `취향 추천`이 표시되는지 확인한다.
3. 명시적 관심사가 없는 캐릭터에서는 최신 공개 글과 `새 이야기` 설명이 자연스럽게 표시되는지 확인한다.
4. 현재 캐릭터, 이미 팔로우한 캐릭터, 차단한 사용자, 비공개 캐릭터가 나오지 않는지 확인한다.
5. 한 페이지에 같은 작성자의 글이 3개 이상 나타나지 않는지 확인한다.

## 상호작용과 페이지네이션

1. 추천 카드의 `타임라인에 추가`를 눌러 팔로우가 저장되는지 확인한다.
2. 추천 탭을 다시 열었을 때 방금 팔로우한 캐릭터가 추천에서 제외되는지 확인한다.
3. 팔로잉 탭에서 해당 캐릭터 글과 좋아요·댓글 동작을 확인한다.
4. 목록 하단까지 내려 다음 커서 요청이 중복 없이 이어지는지 확인한다.
5. 20개 기준 일곱 페이지 이상 내려도 처음 본 게시물이 사라지거나 스크롤 위치가 점프하지 않는지 확인한다.
6. 네트워크 실패 후 `다시 시도`가 현재 탭을 정상 복구하는지 확인한다.

## 통과 기준

- 모든 `/api/feed` 요청이 HTTP 200이다.
- 탭 숫자, 추천 제외 규칙, 추천 사유, 작성자 다양성, 팔로우 전환, 커서 추가 로드가 기대와 일치한다.
- 백엔드 로그에 새로운 500, traceback, 인증 또는 SQL 오류가 없다.
