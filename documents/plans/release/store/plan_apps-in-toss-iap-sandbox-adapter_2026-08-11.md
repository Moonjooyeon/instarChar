# 앱인토스 인앱결제 샌드박스 어댑터 구현 계획

## 목표

앱인토스 샌드박스의 결제 테스트 주문을 운영 결제와 분리해 검증하고, 허용된 테스트 계정에만 테스트 크레딧을 멱등 지급한다. 토스 운영 환경에서는 기존 mTLS 주문 조회와 서버 SKU 검증을 그대로 사용한다.

## 성공 조건

1. 프런트가 공식 `getOperationalEnvironment()` 결과와 구매 SKU를 지급 API에 전달한다.
2. 샌드박스 지급은 서버 플래그, 테스트 계정 HMAC 해시 허용목록, UUID 형식의 샌드박스 주문 ID, 설정된 테스트 상품을 모두 확인한다.
3. 같은 테스트 계정·상품·주문을 반복 요청해도 크레딧은 한 번만 지급되고, 새 UUID 주문은 별도 구매로 지급된다.
4. 샌드박스 구매는 `apps_in_toss_sandbox` 공급자로 기록하고 운영 토스 대사 대상에서 제외한다.
5. 샌드박스 플래그가 꺼졌거나 허용되지 않은 계정, 상품, 주문의 요청은 지급하지 않는다.
6. 운영 환경 요청은 계속 토스 주문 상태 API 검증 결과만 신뢰한다.

## 변경 및 검증

1. 환경설정·검증 규칙 추가 → 잘못된 허용목록/상품 설정 시 애플리케이션 시작 검증 실패
2. 프런트 요청 계약 확장 → 도메인 테스트와 TypeScript 타입 검사
3. 서버 샌드박스 주문 어댑터 추가 → 성공·차단·멱등키 단위 테스트
4. 저장·대사 공급자 분리 → SQL 생성 테스트에서 운영 공급자 조건 확인
5. 배포 가이드 갱신 → 기본값은 비활성화이며 테스트 후 즉시 끄는 절차 명시

## 배포 안전장치

- 기본값 `TOSS_IAP_SANDBOX_ENABLED=false`
- 원문 Toss userKey 대신 기존 서버 HMAC 키로 계산한 64자리 해시만 허용목록에 저장
- 앱인토스 샌드박스가 반환하는 UUID 주문 ID와 fixture SKU만 특별 처리
- 테스트 상품은 운영 콘솔에 등록된 SKU 중 하나만 선택
- 테스트 완료 후 샌드박스 플래그와 테스트 계정 허용목록 제거
