# 앱인토스 인앱결제 구매기록 보존 및 탈퇴 처리 결정

## 결정 요약

로컬 구현 기준은 다음과 같다.

1. 활성 계정의 구매 원장은 사용자 FK, 원문이 아닌 전용 HMAC 사용자 연결값, 주문 ID, SKU, 내부 가격·지급량 스냅샷과 상태를 저장한다.
2. 계정 삭제 유예기간 7일이 끝나 실제 계정을 파기할 때 Apps in Toss `userKey` 연결 끊기 API를 mTLS로 호출한다.
3. 계정 행 삭제로 구매 원장의 `user_id`를 `NULL`로 분리하고, 원문 `userKey`는 저장하지 않는다.
4. 탈퇴 계정의 구매 원장은 각 거래의 `created_at + 5년`까지 보관한다. 이미 5년이 지난 거래는 계정 파기 시점까지만 보관한다.
5. 보존 만료 뒤에는 HMAC이나 주문 ID만 남기지 않고 해당 구매행 전체를 삭제한다.
6. 분쟁·수사·법적 보존 명령 등 별도 사유가 있으면 만료 전에 `retention_until`을 연장하고 근거·승인자·만료일을 운영 기록에 남긴다.

이 결정은 기술적 안전 기준이며 법률 자문 결과가 아니다. 개인정보처리방침, 유료서비스·환불 조항과 실제 보존 목적은 대표자 또는 법무 검토를 거쳐 승인해야 한다. 승인 전에는 신규 결제와 콘솔 상품 노출을 켜지 않는다.

## 공식 근거와 적용

2026-08-11 현재 국가법령정보센터의 전자상거래법 시행령 제6조는 계약·청약철회 기록과 대금결제·재화 등의 공급 기록을 5년, 소비자 불만·분쟁 처리 기록을 3년, 표시·광고 기록을 6개월 보존하도록 정한다. 구매 원장에는 계약·결제·공급 상태가 함께 있으므로 가장 긴 5년을 기본값으로 적용한다.

개인정보 보호법 제21조는 처리 목적 달성 등으로 불필요해진 개인정보를 지체 없이 파기하고, 다른 법령에 따라 보존할 때에는 다른 개인정보와 분리해 저장·관리하며 복구되지 않게 파기하도록 정한다. 이에 따라 구매 원장은 계정 소유 데이터와 다른 테이블·제한된 운영 API로 관리하고, 계정 삭제 후 FK를 제거하며, 만료 뒤 행 전체를 삭제한다.

Apps in Toss 로그인 공식 명세는 파트너 mTLS 인증으로 `remove-by-user-key`를 호출해 사용자 연결을 끊을 수 있다고 명시한다. `alive`는 7일 유예기간 중 재로그인 복구를 유지하기 위해 삭제 요청 시점이 아니라 최종 계정 파기 시점에 연결을 끊는다.

## 데이터 수명주기

| 단계 | 계정 | 구매 원장 | 토스 로그인 연결 | 검증 |
| --- | --- | --- | --- | --- |
| 정상 이용 | 활성 | 사용자 FK와 HMAC 연결값 유지 | 유지 | 사용자 결제 내역·첫 구매 판정 |
| 삭제 요청 후 7일 | 잠금·복구 가능 | 기존 상태 유지 | 유지 | 재로그인 시 삭제 예약 취소 |
| 최종 계정 파기 | 사용자 행 삭제 | `user_id=NULL`, `retention_until=max(created_at+5년, 파기 시각)` | `remove-by-user-key` 호출 | PostgreSQL FK·통합 테스트 |
| 법정 보존 중 | 없음 | 주문·지급·환불·HMAC 최소 원장만 제한 보관 | 해제 | 운영자 보호 API로만 조회 |
| 보존 만료 | 없음 | 구매행 전체 삭제 | 해제 | 계정 삭제 스케줄러 주기 작업 |

## 저장 항목과 최소화

| 항목 | 보존 이유 | 처리 |
| --- | --- | --- |
| `provider_order_id` | 중복 지급 방지, 주문·환불 대조 | 만료 시 구매행과 함께 삭제 |
| `provider_subject_hash` | 재가입 첫 구매 보너스 중복 방지, 탈퇴 후 분쟁 대조 | 전용 HMAC만 저장, 원문 `userKey` 미저장, 만료 시 삭제 |
| `sku`, 상태, 상태 확정·지급·환불 시각 | 계약 이행·상품 지급·환불 증빙 | 만료 시 삭제 |
| `price_krw` | 서버 상품 정책 스냅샷 | 콘솔 실제 판매가와 샌드박스에서 대조 후 사용 |
| 지급·회수 크레딧 | 디지털 상품 공급·환불 정합성 | 만료 시 삭제 |
| 제공자 원문 응답, 액세스 토큰, 원문 `userKey` | 불필요 | 저장하지 않음 |

Apps in Toss 서버 주문 상태 API는 `orderId`, `sku`, `status`, `statusDeterminedAt`, `reason`을 반환하고 실제 결제금액은 반환하지 않는다. 따라서 클라이언트 성공 이벤트의 `amount`를 서버 증빙으로 신뢰하지 않는다. 콘솔 SKU·VAT 포함 판매가와 서버 `price_krw` 정책표의 일치 여부를 샌드박스 및 출시 승인 단계에서 별도로 서명한다.

## 구현 증거

- migration `20260811_0023`이 `credit_purchases.retention_until`과 만료 조회 인덱스를 추가한다.
- 최종 계정 파기 트랜잭션이 구매행 보존 만료를 설정한 뒤 사용자 FK를 `NULL`로 만든다.
- 계정 삭제 스케줄러가 만료된 탈퇴 구매행을 삭제한다.
- Toss 계정 최종 파기 전에 공식 `remove-by-user-key` API를 호출한다. 실패하면 계정을 보존하고 다음 스케줄에서 다시 시도한다.
- 코드 커밋 `f2592e5`; backend 326건과 실제 PostgreSQL 통합 테스트, `0022 → 0023 → 0022 → 0023` migration 검증 통과.

## 고객 노출 문서 변경안

현재 공개 개인정보처리방침과 이용약관은 Toss 로그인, 인앱결제, 유료 크레딧, 환불과 구체적인 법정 보존기간을 설명하지 않는다. 다음 내용이 승인된 뒤 공개 문서를 개정하고 `TERMS_VERSION`을 올려 재동의를 받아야 한다.

- 개인정보처리방침 수집 항목에 Apps in Toss 사용자 식별자, 구매 주문 ID, SKU, 결제·지급·환불 상태와 시각을 추가한다.
- 로그인·결제 제공자로 Apps in Toss 및 비바리퍼블리카 관련 처리 관계를 정확한 계약 역할에 맞춰 기재한다.
- 계약·청약철회 및 대금결제·공급 기록 5년, 소비자 불만·분쟁 처리 기록 3년, 표시·광고 기록 6개월을 표로 기재한다.
- 탈퇴 시 일반 계정 데이터는 7일 뒤 삭제하되 법정 구매 기록은 분리 보관 후 만료 시 삭제한다고 안내한다.
- 이용약관에 유료 크레딧의 성격, 지급 시점, 사용 순서, 청약철회·환불, 미성년자 결제, 서비스 장애, 계정 삭제와 잔여 크레딧 처리 조항을 추가한다.
- 앱 내 결제 화면에서 최종 판매가, 지급량, 환불 안내, 약관·개인정보처리방침 링크를 결제 전에 확인할 수 있게 한다.

## 출시 전 승인 질문

- [ ] 전자상거래법상 통신판매업자 표시·신고와 구매안전 관련 적용 범위를 확인했다.
- [ ] `credit_purchases`의 5년 분리 보관과 HMAC 기반 부정 이용 방지 목적을 개인정보처리방침에 기재해도 되는지 승인했다.
- [ ] 회사의 세법·회계·소송 보존 의무가 5년보다 긴 거래를 별도로 요구하는지 확인했다.
- [ ] 법적 보존 정지 시 `retention_until` 연장 권한·승인·해제 절차를 정했다.
- [ ] 유료서비스·청약철회·환불·미성년자·잔여 크레딧 조항을 승인했다.
- [ ] 개정 약관 시행일, 사전 고지 기간과 기존 사용자 재동의 방식을 승인했다.
- [ ] Apps in Toss가 개인정보 처리위탁, 제3자 제공 또는 독립 처리자 중 어디에 해당하는지 계약 문서 기준으로 확정했다.
