# ALIVE 첫 150C 보상 미션 UI 계획

## 목표

가입·첫 캐릭터·첫 DM으로 지급되는 총 150C를 사용자가 놓치지 않고 따라가도록, 기존 도움말과 분리된 이야기형 미션 UI를 제공한다. `AI 기능 체험` 같은 기술 표현 대신 `시작의 세 장면`이라는 제품 언어로 현재 단계와 다음 행동을 보여준다.

## 가정

- 서버는 `signup`, `first_character`, `first_dm`을 사용자별 한 번만 지급한다.
- 각 보상은 50C이며 기존 지급 조건과 금액을 변경하지 않는다.
- 사용자는 크레딧을 `포인트`보다 앱 표기 단위인 `C`로 인식한다.
- 미션 완료 상태는 잔액에서 추정하지 않고 서버 `reward_grants`를 기준으로 한다.
- 로컬 모드에서는 서버 보상 상태를 확인할 수 없으므로 미션 UI를 노출하지 않는다.

## 범위

- 크레딧 잔액 API에 3개 미션의 코드·금액·완료 상태를 추가한다.
- 홈 첫 화면에 캐릭터 생성으로 이어지는 현재 미션 카드를 표시한다.
- 캐릭터 피드에 첫 대화로 이어지는 현재 미션 카드를 표시한다.
- 크레딧 화면에 3개 미션 전체 진행도와 완료 도장을 표시한다.
- 캐릭터 저장과 DM 완료 후 미션 상태가 즉시 갱신되도록 잔액 갱신 이벤트를 연결한다.
- 순수 도메인 규칙, API 계약, 핵심 E2E 시나리오를 테스트한다.

## 제외 범위

- 신규 보상, 일일 미션, 출석, 연속 접속, 업적 시스템
- 보상 금액이나 지급 조건 변경
- 기존 서비스 투어와 피드 도움말 제거·변경
- 새로운 DB 테이블이나 migration
- 분석 이벤트·푸시 알림·결제 활성화

## 영향 경로

```text
RewardGrant -> GET /api/credits -> 미션 진행 모델
-> 홈의 다음 장면 CTA -> 캐릭터 저장 -> first_character 50C
-> 피드의 다음 장면 CTA -> 첫 DM 성공 -> first_dm 50C
-> 잔액 갱신 이벤트 -> 크레딧 화면의 3/3 완료 상태
```

## 구현 단계

1. 서버가 현재 사용자의 보상 grant를 미션 상태로 반환한다.
2. 프런트 도메인에서 순서·현재 단계·버튼 문구를 계산한다.
3. `시작의 세 장면` 전체 카드와 화면별 다음 미션 카드를 구현한다.
4. 홈·피드·크레딧 화면의 기존 행동에 CTA를 연결한다.
5. 캐릭터 저장 후 잔액 갱신 이벤트를 추가하고 테스트한다.

## 성공 조건

- 신규 사용자는 가입 보상 완료와 `1 / 3` 진행도를 본다.
- 첫 캐릭터 저장 후 `2 / 3`, 첫 DM 성공 후 `3 / 3`으로 표시된다.
- 각 단계에 `+50C`, 전체에 `총 150C`가 명확하게 표시된다.
- 미완료 단계의 버튼이 실제 다음 화면으로 이동한다.
- 모든 단계 완료 후 홈·피드의 안내 카드는 사라지고 크레딧 화면에는 완료 기록이 남는다.
- UI 문구에 `AI`, 모델명, 생성 기술 설명을 사용하지 않는다.
- 기존 도움말 오버레이와 독립적으로 동작한다.

## 검증 계획

- backend credit repository·API test
- frontend mission domain test와 API adapter test
- TypeScript typecheck, frontend domain test, production build
- Playwright mock 시나리오에서 1/3 → 2/3 → 3/3 확인
- 실행 중인 앱이 있을 때 모바일 폭에서 홈·피드·크레딧 화면 확인

## 위험과 롤백

- 클라이언트 상태로 완료를 추정하면 실제 지급과 어긋날 수 있으므로 서버 grant만 사용한다.
- 여러 화면의 카드가 과도하게 느껴질 수 있어 홈·피드에서는 현재 미션 하나만 표시하고 완료 후 숨긴다.
- API 실패 시 가짜 진행도를 표시하지 않고 미션 UI만 조용히 숨긴다.
- 문제가 생기면 미션 컴포넌트 연결과 응답 필드만 제거할 수 있으며 기존 지급 로직에는 영향이 없다.

## 구현 및 검증 결과

- 서버 `RewardGrant`를 기준으로 `signup`, `first_character`, `first_dm` 완료 상태를 반환한다.
- 홈·피드에는 현재 미션 하나, 크레딧 화면에는 전체 3단계와 완료 기록을 표시한다.
- 캐릭터 저장과 첫 DM 성공 후 기존 잔액 갱신 이벤트로 진행도를 다시 조회한다.
- backend: `257 passed`
- frontend domain: `140 passed`
- TypeScript typecheck: 통과
- Vite production build: 통과
- Playwright E2E 시나리오는 추가했으나 실행 중인 앱 프로세스가 없어 미실행했다.
- 모바일 실화면 QA도 같은 이유로 미실행했으며, 저장소 규칙에 따라 검증용 프로세스를 새로 시작하지 않았다.
