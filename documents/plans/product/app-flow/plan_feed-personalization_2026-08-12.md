# 추천 피드 개인화와 탭 표시 개선

## 목표

추천 탭이 현재 캐릭터의 관심사와 실제 팔로우·좋아요 성향을 반영하면서도 최신성과 작성자 다양성을 유지하도록 개선한다. 팔로잉과 추천 탭에는 전체 개수로 오해할 수 있는 지연 로드 개수를 표시하지 않는다.

## 가정

- 사용자의 "내 관심사"는 현재 선택된 캐릭터의 관심사·세계관·성격과 그 캐릭터가 만든 팔로우·좋아요 이력이다.
- `내 글` 숫자는 현재 캐릭터의 실제 게시글 개수이므로 유지한다.
- 초기 운영 규모에서는 별도 ML 모델보다 설명 가능하고 결정적인 점수 기반 랭킹이 장애 대응과 품질 검증에 유리하다.
- 기존 공개 캐릭터 태그는 비정규 문자열일 수 있으므로 읽기 호환성을 유지해야 한다.

## 범위

- 추천 용어를 서버에서 일관되게 정규화하고 공개 캐릭터 태그의 서버 권한 저장에 적용한다.
- 현재 캐릭터 설정, 팔로우 대상, 좋아요 대상의 특성을 가중치로 결합한다.
- 추천 결과를 관련도 우선, 최신순으로 정렬하고 한 페이지에서 동일 작성자의 과다 노출을 제한한다.
- 자기 캐릭터, 이미 팔로우한 캐릭터, 차단 관계, 비공개 캐릭터 제외 규칙을 유지한다.
- 팔로잉·추천 탭의 지연 로드 배열 개수를 제거한다.
- 추천 API, 커서, 태그 정규화, UI 계약에 회귀 테스트를 추가한다.

## 제외 범위

- 추천 노출·체류 시간·클릭·`관심 없음` 이벤트를 새로 수집하는 분석 시스템
- 외부 추천 서비스나 머신러닝 모델 도입
- 추천 탭에서 팔로우 전 좋아요를 허용하는 상호작용 정책 변경
- 프로덕션 배포 실행과 앱스토어 제출

## 영향 경로

```text
추천 탭 클릭
-> FeedTimeline
-> useAliveFeed / useFeedPagination
-> GET /api/feed?kind=recommendations
-> FeedRepository
-> characters + shared_characters + character_follows + character_post_likes + public_feed_posts
-> FeedPage 응답
-> 추천 사유 표시와 무한 스크롤
```

캐릭터 저장 또는 게시글 갱신 시 `CharacterRepository`와 `CharacterPostsRepository`가 동일한 추천 태그 정규화 규칙으로 공개 스냅샷을 갱신한다.

## 구현 단계

1. 추천 용어 정규화 도메인 헬퍼와 경계값 테스트를 추가한다.
2. 공개 태그 저장을 서버 계산값으로 통일하고 기존 비정규 태그 읽기 호환성을 유지한다.
3. 설정·팔로우·좋아요 가중치와 페이지 내 작성자 다양성을 추천 쿼리에 적용한다.
4. 공개·운영상태·자기·팔로잉·차단 제외를 적용한 최신 게시글 후보군을 제한하고 그 안에서 개인화 점수를 계산한다.
5. 점수 정렬을 포함하는 서명 커서와 추천 사유 응답을 검증한다.
6. 팔로잉·추천 탭 숫자를 제거하고 프런트 계약 테스트를 갱신한다.
7. 커서 페이지가 120개를 넘어도 기존 게시글을 제거하지 않고 복합 ID 중복만 제거한다.

## 성공 조건

- 쉼표·공백·기호가 섞인 관심사가 동일한 정규화 규칙으로 매칭된다.
- 현재 캐릭터의 명시적 관심사가 행동 신호보다 우선하고, 팔로우·좋아요 성향도 추천 점수에 반영된다.
- 관련도 점수가 같으면 최신 게시글이 먼저 노출된다.
- 한 추천 페이지에서 동일 캐릭터 게시글이 최대 2개만 노출된다.
- 기존 자기 자신·팔로잉·차단·비공개 제외 규칙과 무한 스크롤 커서가 유지된다.
- 팔로잉·추천 탭에는 클릭 전후 모두 숫자가 나타나지 않는다.
- 공개 게시글 5만 건의 로컬 운영 유사 데이터에서 추천 연속 페이지 응답이 300ms 이내다.
- 120개를 넘겨 추가 로드해도 이전 게시글, 순서와 스크롤 연속성이 유지된다.
- 프런트 전체 게이트와 백엔드 전체 테스트가 통과한다.

## 검증 계획

- `npm run typecheck`
- `npm run test:domain`
- `npm run build`
- `PYTHONPYCACHEPREFIX=/private/tmp/instarChar-pycache backend/.venv/bin/python -m compileall -q backend/app backend/tests backend/migrations`
- `PYTHONPATH=backend backend/.venv/bin/pytest backend/tests`
- 실행 중인 앱이 있으면 `/app/feed`에서 탭 숫자, 추천 사유, 페이지 추가 로드를 확인한다.
- 실행 중인 PostgreSQL이 있으면 현재 마이그레이션 헤드와 피드 API 통합 동작을 확인한다.

## 위험과 롤백

- 동적 관련도 계산은 단순 최신순보다 쿼리 비용이 크다. 최신 후보 2,400개를 먼저 생성하고 추천 용어 수와 페이지 스캔 배수를 제한한다.
- 기존 태그는 다음 캐릭터 또는 게시글 저장 전까지 비정규 상태일 수 있다. 추천 문서의 문자열 호환 매칭으로 누락을 방지한다.
- 페이지 다양성 제한으로 한 페이지의 표시 개수가 20개보다 적을 수 있으나 다음 커서는 실제 스캔 위치를 사용해 중복을 방지한다.
- 문제가 발생하면 `FeedRepository`의 랭킹 변경과 공개 태그 정규화 호출, 탭 마크업만 되돌린다. 스키마 변경이 없어 데이터 롤백은 필요하지 않다.
