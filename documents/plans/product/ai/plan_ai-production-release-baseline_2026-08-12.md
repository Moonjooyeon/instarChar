# AI 기능 운영 출시 기준선 구현 계획

## 목표

- 무료 보조 AI를 유료 DM·콘텐츠 생성의 우회 경로로 사용할 수 없게 한다.
- 정상적인 짧은 사용은 부담 없이 유지하면서 긴 맥락과 재시도로 생기는 구조적 적자를 제한한다.
- 모든 AI 호출에 실제 공급자 모델, 토큰, 계산 원가, 프롬프트 버전을 남긴다.
- 서버가 flow별 출력 계약과 안전 지시를 소유하고, 캐릭터 말투·기억·비반복 품질을 안정화한다.
- 사용자가 요청 전에 결제 수단, 회당 가격, 일일 한도, 무료 포함 기능을 이해하게 한다.
- 정상 사용 P95 원가 가정에서 유료 AI 기능별 공헌이익률 25% 이상을 목표로 한다.

## 가정

- 운영 모델은 Flash `gemini-3.6-flash`, Pro `gemini-3.1-pro-preview`다.
- 표준 원가는 Flash 입력/출력 100만 토큰당 `$1.50/$7.50`, Pro `$2.00/$12.00`으로 계산한다.
- 앱인토스 정상 정산과 첫 구매 대형 상품을 고려한 보수 매출은 크레딧당 약 `6.22원`이다.
- 사용자 경험상 기본 DM 1C와 자동 근황 2C는 유지하고, 손실 위험이 큰 기억 반영과 Pro만 가격을 조정한다.
- 무료 댓글·관계·기억 보조는 상품 포함 혜택으로 유지하되, 범용 생성 API에서는 차단한다.

## 범위

1. 공개/서버 전용 AI flow 경계와 무료 보조 기능 전용 계약
2. 기능별 크레딧·에너지·입력·출력·사고 토큰·재시도 정책
3. 공급자 모델·토큰·원가·프롬프트 버전 영속화
4. DM·피드·캐릭터 분석·보조 기능의 서버 소유 출력 계약
5. 크레딧 카탈로그, DM 선택, 생성 화면, 자동 근황 안내 UI
6. 권한·원가·스키마·환급·프롬프트·표시 가격 회귀 테스트

## 제외 범위

- MonoGPT 계약 단가 협상과 앱인토스 실제 정산서 대사
- 새로운 AI 공급자 추가 또는 모델 A/B 실험 플랫폼
- 앱 전역 디자인 개편과 크레딧 상품 가격 자체의 변경
- 이미 적용된 데이터베이스 마이그레이션 수정

## 영향 경로

```text
사용자 DM·피드·설정 행동
-> React 기능 훅과 비용 안내
-> 기능별 API 요청
-> FastAPI 공개/보조 전용 라우트
-> 서버 소유 flow 정책·프롬프트 계약
-> 크레딧/에너지 예약
-> MonoGPT Gemini 호출
-> 실제 토큰·원가 정산
-> 출력 검증·저장
-> 크레딧 확정 또는 환급
-> 잔액·사용 내역 UI 갱신
```

## 구현 단계

1. 가격 기준을 기본 DM 1C, 기억 반영 3C, Pro 9C, 피드 3C, 자동 근황 2C, 캐릭터 분석 10C로 갱신한다. 첫 캐릭터 분석은 무료다.
2. 기억 반영·Pro·피드의 입력 기록 수, 출력 토큰, 사고 토큰을 실제 UI 계약에 맞게 줄이고 Pro의 자동 재시도를 제한한다.
3. `assist_*`를 범용 공개 flow에서 제외하고, 목적·출력 형식·토큰 한도가 고정된 보조 요청 계약으로만 호출한다.
4. 모든 flow에 버전이 있는 서버 출력 계약을 합성하고, JSON/숫자/enum 결과는 서버에서 검증한다.
5. 공급자 응답 토큰으로 USD 원가를 계산하고 구체 모델명과 프롬프트 버전을 사용 기록에 저장한다.
6. 카탈로그와 요청 직전 UI에서 새 가격, 구매 전용 여부, 포함 혜택, 한도와 환급 기준을 표시한다.
7. 정적 테스트, 빌드, 마이그레이션 검사, 기존 프로세스 QA와 출시 환경 설정 감사를 수행한다.

## 성공 조건

- 인증 사용자가 범용 `/api/ai/generate`에 임의의 `assist_*`, `internal*`, `auto_feed_post`를 보내면 공급자 호출 전에 거절된다. 이전 앱의 알려진 보조 요청 키는 같은 고정 계약으로만 호환한다.
- 무료 보조 요청은 정해진 기능·필드·출력 계약으로만 실행되고 임의의 모델·flow·최대 토큰을 선택할 수 없다.
- 기억 반영 3C와 Pro 9C, 재분석 10C가 서버 카탈로그, DM 선택 UI, 예상 차감, 실제 원장에 일치한다.
- 정상 성공 기록에 구체 모델명, 입력/후보/사고/전체 토큰, 0보다 큰 계산 원가, 프롬프트 버전이 남는다.
- 실패·취소·빈 응답·잘못된 구조·저장 실패는 크레딧을 확정하지 않으며 공급자 원가는 별도로 기록된다.
- 프롬프트 회귀 검증이 정상, 빈 입력, 잘못된 JSON, 프롬프트 주입, 반복, 경계 길이를 포함한다.
- 백엔드 전체 테스트, 프론트 타입 검사·도메인 테스트·빌드, 마이그레이션 검사가 통과한다.

## 검증 계획

- 백엔드: flow 공개 권한, 가격, 예약/확정/환급, 원가 계산, 구체 모델 저장, 출력 계약 집중 테스트
- 프론트: DM 모드 가격, 카탈로그 표시, 부족 상태, 자동 근황 비용, 생성 직전 안내 도메인 테스트
- AI: 고정 fixture로 출력 스키마, 캐릭터 일관성, 주입 방어, 비반복, 토큰 상한을 결정적 검사와 정성 검사로 분리
- 통합: 기존 실행 중 프로세스가 있으면 로그인 상태에서 DM·피드·크레딧 화면을 확인하고, 없으면 수동 검토 절차를 남김
- 운영: 배포 환경의 모델명, 단가, 일일/월간 한도, 스케줄러, 마이그레이션 head를 읽기 전용으로 감사

## 위험과 롤백

- 가격 변경은 기존 사용자의 체감 비용을 높인다. 서버 정책 버전을 올리고 UI 카탈로그를 함께 배포하며, 문제 시 이전 가격 상수와 프론트 표시를 한 커밋으로 되돌린다.
- 맥락 축소는 기억 품질을 낮출 수 있다. 최근 대화보다 요약 기억을 우선하고 fixture 정성 평가가 실패하면 기록 수만 단계적으로 복원한다.
- 보조 API 분리는 기존 자동 댓글·관계·기억 처리를 끊을 수 있다. 프론트 전환과 서버 라우트를 같은 배포 단위로 제공하고 실패 시 기존 결정적 fallback을 유지한다.
- 원가 계산 오류는 월 한도를 과도하게 소진할 수 있다. 공급자 토큰 메타데이터가 완전할 때만 실측 정산하고, 불완전하면 기존 보수 예약액을 유지한다.
- 새 마이그레이션은 기존 열을 삭제하거나 재해석하지 않고 nullable/default 기반으로 추가하며, 출시 전 스테이징 적용과 downgrade SQL을 검토한다.

## 구현·검증 결과

- 임의의 무료 `assist_*` 공개 호출은 차단하고, 새 전용 보조 API와 이전 앱의 알려진 요청 키만 고정 flow·토큰·출력 계약으로 처리한다.
- 서버가 모델을 선택하며 이전 앱의 `model` 필드는 호환 목적으로 받되 무시한다. 새 프런트는 모델명을 보내지 않는다.
- 공급자 모델명, 입력·후보·사고·전체 토큰, 계산 USD 원가, 프롬프트 버전을 사용 기록에 저장하도록 구현했다.
- AI·크레딧·피드 생성·마이그레이션 관련 백엔드 184개가 통과하고 1개가 환경 조건으로 스킵됐다. Alembic head는 `20260812_0024`다.
- 프런트 타입 검사, 도메인 테스트 160개, 프로덕션 빌드가 통과했다.
- 전체 백엔드 테스트는 387개가 통과하고 1개가 환경 조건으로 스킵됐다.
- 실행 중인 프런트·백엔드 프로세스가 없어 브라우저 E2E는 새 프로세스를 시작하지 않고 보류했다.
