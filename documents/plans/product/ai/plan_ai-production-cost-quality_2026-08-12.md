# AI 운영 비용·품질·UX 개선 계획

## 목표

- 사용자가 직접 요청한 생성은 명확한 크레딧 정책을 유지한다.
- 자동 보조 AI는 사용자에게 무료로 제공하되, 자동 피드만 할인된 구매 크레딧으로 제공한다.
- Pro 기반 캐릭터 분석은 최초 1회만 무료로 제공하고 이후에는 구매 크레딧을 사용한다.
- 자동 피드가 최근 글의 장면·문구·구조를 반복하지 않도록 프롬프트와 검증 경계를 강화한다.
- 자동 게시의 기본 빈도를 6시간으로 제공하고, UI에서 할인 가격과 잔액 부족 중단을 설명한다.

## 변경 범위

1. 서버 flow 정책과 크레딧 예약
2. Gemini 생성 설정과 피드 생성 프롬프트/중복 검증
3. 캐릭터 생성·피드 설정·크레딧 안내 UI
4. 정책·중복·생성 설정 회귀 테스트

## 비범위

- MonoGPT의 비공개 크레딧 단가 변경
- 기존 유료 DM과 수동 피드의 크레딧 가격 변경
- 자동 보조 AI를 별도 사용자 결제로 전환

## 검증 기준

- 첫 캐릭터 분석은 0C이고, 성공한 두 번째 분석부터 5C 구매 크레딧을 예약한다.
- `assist_*` flow와 자동 피드는 각각의 일일 상한을 초과하면 공급자 호출 전에 차단된다.
- 피드 생성 요청에는 최근 글, 생성 시각, 요청별 다양성 시드와 비반복 지시가 포함된다.
- 동일하거나 매우 유사한 자동 피드는 저장하지 않고 환급된다.
- 프론트엔드가 자동 게시 2C 가격과 캐릭터 분석 가격을 정확히 안내한다.

## 구현 및 검증 결과

- 첫 `character_analysis`는 Pro 품질로 무료 예약되고, 이후 성공 요청은 구매 크레딧 5C만 사용한다.
- 무료 보조 flow에는 flow별 일일 상한을 적용했다. SNS 보조는 12회, 관계 보조는 6회, 세션 정리는 4회다.
- 자동 피드 무료 운영 결정은 아래 유료 운영 전환으로 대체됐다.
- 피드의 다양성 시드·최근 글 비반복 지시·유사도 차단과 환급을 추가했다.
- 2026-08-12 기준: 백엔드 351 통과/1 스킵, 프론트 타입 검사·도메인 159개·프로덕션 빌드 통과.

## 자동 피드 유료 운영 전환

### 결정

- 자동 피드는 구매 크레딧만 글 1개당 2C 사용한다. 수동 생성 3C보다 1C 저렴하다.
- 1시간, 6시간, 12시간 주기를 제공한다. 시간당 자동 게시의 하루 최대치는 24개다.
- 구매 크레딧이 2C 미만이면 자동 게시를 서버에서 끄고 다음 예약을 지운다. 보너스 크레딧과 에너지는 사용하지 않는다.
- 기존 로컬의 900초 설정도 서버 기동을 막지 않도록 설정값을 숫자로 다시 허용하되, 사용자가 고르는 UI 옵션은 1시간 이상만 제공한다.

### 검증 기준

- 자동 글 성공 시 구매 크레딧 2C만 예약·커밋된다.
- 구매 크레딧이 부족한 자동 글은 공급자 호출 없이 자동 게시가 중단되고 안내 사유가 저장된다.
- 1시간 주기 선택은 API·스케줄러·UI에서 일관되게 유지된다.

### 구현 및 검증 결과

- `auto_feed_post`는 구매 크레딧 2C만 사용하며, 에너지·보너스 크레딧은 차감하지 않는다.
- `CREDIT_INSUFFICIENT`이면 공급자 호출 전에 자동 게시를 끄고 다음 예약을 제거한다.
- 2026-08-12 기준: 백엔드 351 통과/1 스킵, 프론트 타입 검사·도메인 159개·프로덕션 빌드 통과.

## 근황 루틴 UX 보완

### Problem

- 현재 자동 근황 설정은 ‘캐릭터 글 설정’을 열고 다시 드롭다운과 하단 안내를 읽어야 한다. 사용자가 현재 선택·24시간 최대 사용량·잔액 부족 시 동작을 한 번에 알기 어렵다.
- 크레딧 화면의 기본 사용 순서는 자동 근황과 Pro의 예외를 충분히 드러내지 못한다.

### Outcome

- 설정을 열기 전에도 선택한 루틴과 24시간 최대 사용량을 확인한다.
- 주기 선택지 자체에서 빈도와 비용을 함께 비교하고, 비용이 늘어나는 변경은 확인 후 적용한다.
- 크레딧 화면에서 자동 근황·Pro·포함 혜택의 서로 다른 규칙을 분명히 구분한다.

### Evidence and scope

- 대상은 `FeedComposer`, `CreditChargeOrder`, `CreditFlowCatalog`과 기존 테마 CSS다.
- 서버 가격·예약·일일 한도는 이미 권한 있는 서버 정책으로 구현되어 있으므로 변경하지 않는다.

### Acceptance criteria

- 12시간/6시간/1시간을 각각 가끔/보통/자주와 24시간 최대 4C/8C/48C로 읽을 수 있다.
- 자동 근황 2C는 구매 크레딧만 쓰며, 잔액 부족 시 멈춘다는 설명이 크레딧 화면과 설정 화면에 일관되게 있다.
- 기존 타입 검사·도메인 테스트·프로덕션 빌드가 통과한다.

### 구현 및 검증 결과

- 접힌 ‘근황 루틴’ 행에도 상태, 주기, 24시간 최대 비용을 함께 보여 준다.
- 설정 안에서는 가끔(12시간·4C), 보통(6시간·8C), 자주(1시간·48C)를 바로 비교한다. 비용이 늘어나는 변경과 시작은 기존 확인 단계를 거친다.
- 크레딧 화면은 일반 기능의 차감 순서와 자동 근황·Pro·포함 혜택의 예외를 분리해 설명한다.
- 브라우저에 실행 중인 앱 탭이 없어 실제 화면 캡처 검토는 하지 못했다. 정적 타입 검사·도메인 테스트·프로덕션 빌드로만 검증한다.

## 예약·확정·환급 안내 보완

- 기본 6시간 루틴은 별도 확인 카드 없이 시작하고, 하루 최대 48C인 1시간 루틴만 확인한다.
- 루틴 카드 안에 “사용과 환급 기준”을 넣어 2C 예약, 저장 시 확정, 빈 응답·중복·저장 실패 시 환급을 설명한다.
- 루틴을 끄면 이후 예약은 멈추지만 이미 공급자 호출이 시작된 한 편은 저장까지 마무리될 수 있음을 명시한다.
- 2026-08-12 기준: 프론트 타입 검사·도메인 테스트 159개·프로덕션 빌드, 예약·환급·자동 루틴 백엔드 집중 테스트 60개를 통과했다.

## 근황 루틴 변경 규칙

- 빈도 선택은 먼저 초안으로만 바꾸고, 시작·변경·중단 버튼을 눌러야 서버 일정이 바뀐다. 1시간·6시간·12시간 모두 동일한 방식이다.
- 실행 중 주기를 바꾸면 다음 근황은 기존 예정 시각과 새 간격 중 더 이른 쪽으로 잡고, 그 다음부터 새 간격을 사용한다. 예정 시각이 지났다면 새 간격 기준으로 다시 잡는다.
- 선택한 1시간 주기는 즉시 화면에 반영되며, 버튼에 24시간 최대 48C가 함께 보여 비용이 숨어 있지 않다.

## UX·비용 보완

- 자동 피드의 기본 주기는 6시간으로 두고, 1시간 선택 또는 자동 시작 전에는 예상 최대 사용량을 확인한다.
- 자동 글의 재생성·환급 실패도 서버에 기록해 실제 재시도와 화면 안내가 일치하게 한다.
- 자동 글 2C가 카탈로그와 사용 내역에서 모두 같은 이름으로 보이게 한다.
- 무료 보조 AI의 일일 상한은 SNS 12회, 관계 6회, 기억 정리 4회로 낮춘다.
- 사용자가 보는 말은 “자동 게시”보다 캐릭터의 행동에 가까운 “혼자 남기는 근황”으로 바꾼다.

### 구현 및 검증 결과

- 기본 주기를 6시간으로 바꿨다. 자동 시작과 더 자주 남기기 전에는 주기별 하루 최대 사용량을 먼저 보여 준다.
- 중복으로 환급된 자동 글도 실패 기록과 재시도 일정에 남긴다. 화면의 “다시 작성 중” 안내와 실제 동작이 일치한다.
- 자동 글 2C는 카탈로그와 사용 내역에서 모두 “혼자 남기는 근황”으로 보인다.
- 2026-08-12 기준: 백엔드 351 통과/1 스킵, 프론트 타입 검사·도메인 159개·프로덕션 빌드 통과.
