# 라이트·다크 테마 및 Tailwind CSS 단계적 전환 계획

## 목표

- 라이트, 다크, 기기 설정 연동 모드를 제공하고 사용자 선택을 로컬에 보존한다.
- 색상, 타이포그래피, 모서리, 그림자를 의미 기반 디자인 토큰으로 관리한다.
- 기존 전역 CSS를 Tailwind CSS 유틸리티로 화면군별 전환한다.
- 기능 동작, 네이티브 safe area, 반응형 레이아웃을 유지한다.
- 각 작업 단위마다 수정 전후 검증을 수행해 회귀 범위를 좁힌다.

## 현재 상태

- Tailwind CSS는 설치되어 있지 않다.
- `apps/frontend/src/appStyles.ts`에 1,327줄의 CSS가 문자열로 포함되어 런타임에 주입된다.
- JSX의 `className` 사용 지점은 629개이며, 대부분 `al-*` 전역 클래스에 연결된다.
- 색상은 다크 모드 기준으로 하드코딩되어 있고 동일 값이 여러 화면에 반복된다.
- 2026-08-05 기준 타입 검사, 96개 도메인 테스트, 프로덕션 빌드가 통과한다.

## 디자인 원칙

- 라이트 모드는 순백색 대신 따뜻한 종이색 바탕과 잉크색 본문으로 캐릭터 기록물의 인상을 만든다.
- 다크 모드는 기존의 자주빛 밤 분위기를 유지하되 배경과 콘텐츠 표면의 명도 차이를 명확히 한다.
- 보라와 핑크는 브랜드 및 상호작용 상태에 제한하고, 넓은 면적의 장식용 그라디언트 사용을 줄인다.
- 색상 토큰은 실제 색 이름이 아닌 역할(`canvas`, `surface`, `ink`, `border`, `accent`, `danger`)로 명명한다.
- 라이트·다크 간 컴포넌트 구조와 정보 위계는 동일하게 유지한다.

## 전환 순서

### 0. 기준선과 기반

- Tailwind CSS v4 Vite 플러그인을 추가한다.
- 런타임 CSS 문자열 주입을 정적 CSS import로 전환한다.
- 의미 기반 테마 토큰과 `data-theme` 기반 다크 변형을 정의한다.
- 기기 설정, 사용자 선택 저장, 초기 렌더 테마 적용을 구현한다.

### 1. 앱 셸과 홈

- 앱 배경, 모바일 프레임, 홈 계정 바, 캐릭터 목록, 빈 상태를 토큰화한다.
- 홈 화면에 라이트, 다크, 기기 설정 선택 UI를 추가한다.
- 새 UI부터 Tailwind 유틸리티를 사용한다.
- 전환되지 않은 화면은 `theme-ready` 범위 밖에서 기존 다크 토큰을 유지해 혼합 테마 회귀를 막는다.

### 2. 로그인과 캐릭터 설정

- 인증, 서비스 투어, 설정 입력, 확인 화면을 전환한다.
- 입력, 버튼, 진행 상태의 공통 패턴을 shared UI로 수렴한다.

### 3. 피드

- 프로필, 작성기, 타임라인, 댓글, 도움말 순으로 나눈다.
- 게시물 본문과 보조 정보의 명도 대비를 두 모드에서 검증한다.

### 4. 탐색과 DM

- 탐색 목록, DM 목록, 대화방, 관계·기억 패널 순으로 나눈다.
- 메시지 발신자 구분이 색상 하나에만 의존하지 않게 유지한다.

### 5. 모달과 레거시 제거

- 공통 모달, 오류, 경고, 성공 상태를 토큰화한다.
- 사용하지 않는 `al-*` 규칙을 확인 후 제거한다.
- 하드코딩 색상은 브랜드 자산과 불변 오버레이를 제외하고 제거한다.

## 단위별 검증

각 작업 단위는 다음 순서를 반복한다.

1. 수정 전 대상 화면과 관련 셀렉터를 기록한다.
2. 대상 화면만 토큰 및 Tailwind로 전환한다.
3. `npm run typecheck`, `npm run test:domain`, `npm run build`를 실행한다.
4. 이미 실행 중인 앱에서 모바일 폭과 데스크톱 프레임을 라이트·다크 각각 확인한다.
5. 실행 중인 앱이 없으면 새 프로세스를 시작하지 않고 수동 검토 절차를 남긴다.

## 완료 조건

- 라이트, 다크, 기기 설정 모드가 초기 진입부터 일관되게 적용된다.
- 모든 주요 화면에서 배경, 텍스트, 경계선, 입력, 상태색이 테마 토큰을 사용한다.
- 주요 화면 컴포넌트가 Tailwind CSS를 기본 스타일 방식으로 사용한다.
- 기존 런타임 CSS 문자열과 사용하지 않는 레거시 셀렉터가 제거된다.
- 타입 검사, 도메인 테스트, 프로덕션 빌드가 통과한다.
- 이미 실행 중인 앱에서 주요 동선의 기능 및 시각 회귀 검증이 완료된다.
